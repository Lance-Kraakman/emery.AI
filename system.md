```

    │                                            │
    ↓ start()                                    │

              ├── timeout() ──────────→ timeout  │

                                            ↓ resumeFromHuman()
                                        pending (scheduler resumes)
```

### Recommendations

1. **Consolidate entry points**: All execution should go through `ExecutionRouter`
2. **Remove adapters.py**: Legacy compatibility layer adds confusion
3. **Single initialization**: `TaskExecutor` should be the only Python entry point
4. **Clear mode flags**: `autonomous_mode` should be explicit, not implicit

# AUTONOMOUS MODE ANALYSIS

## Current Implementation

### Where autonomous_mode is set:

1. **CoordinatorRequest.autonomous_mode**: Passed from TypeScript
2. **RuntimeContext.autonomous_mode**: Used in graph nodes
3. **Adapters implicit**: `adapters.py` always sets `autonomous_mode=True` for tasks

### Behavior when autonomous_mode=True:

| Component | Normal (Interactive) | Autonomous |
|-----------|---------------------|------------|
| Clarifying questions | Asks user | Skipped |
| Plan approval | Awaits user | Auto-approved (if low-risk) |
| `ask_question` tool | Available | Excluded |
| Human-in-the-loop | Enabled | Disabled |

### Issue: Implicit vs Explicit

The adapter layer always sets `autonomous_mode=True`, making it unclear when interactive mode would be used for tasks. This should be explicit based on trigger type.
