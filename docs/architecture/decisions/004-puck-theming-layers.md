# ADR-004: Puck Theming Layers

**Status:** Accepted
**Date:** 2025-01-14
**Context:** Puck Frontend Refactor Phase 1

## Context

Puck implementation uses multiple styling approaches without clear distinction:
- CSS Modules in blocks
- Tailwind utilities
- Inline styles
- Global CSS (puck-theme.css)
- Theme CSS variables

This creates confusion about:
- Where to put styles
- How theming works
- What users can customize
- What's fixed editor UI

## Decision

**Three distinct theming layers with different purposes and technologies.**

---

## Layer 1: App Themes (User-Controlled)

### Purpose
End-user customization of their published app appearance.

### Technology
CSS custom properties (variables) generated by `ThemeConfig` value object.

### Scope
- App-level: Default theme for all pages
- Page-level: Optional override of app theme
- Hierarchical: Page theme merges with app theme

### User Control
- Editable via Theme Editor in Puck sidebar
- Live preview in editor
- Saved to database
- Applied to published pages

### Implementation
```typescript
// Domain: ThemeConfig value object
export class ThemeConfig {
  static create(props: ThemeConfigProps): ThemeConfig { /* ... */ }
  static merge(base: ThemeConfig, override: ThemeConfig): ThemeConfig { /* ... */ }

  // Generates CSS variables
  toCSSVariables(): Record<string, string> {
    return {
      '--theme-primary': this._config.colors.primary,
      '--theme-background': this._config.colors.background,
      '--theme-text': this._config.colors.text,
      // ... all theme values
    };
  }
}

// Applied at Root component
export const Root = {
  render: ({ children, puck }) => {
    const theme = useTheme();
    const cssVariables = theme.toCSSVariables();

    return (
      <div style={{ ...cssVariables }}>
        {children}
      </div>
    );
  }
};
```

### Available Variables
```css
/* Colors */
--theme-primary
--theme-secondary
--theme-background
--theme-surface
--theme-text
--theme-text-muted
--theme-border
--theme-link
--theme-success
--theme-warning
--theme-error

/* Typography */
--theme-font-family
--theme-font-size
--theme-heading-color
--theme-heading-font-weight

/* Layout */
--theme-spacing-unit
--theme-spacing-scale
--theme-border-radius
--theme-border-width
```

### Usage in Blocks
```css
/* styles.module.css */
.container {
  background: var(--theme-background);
  color: var(--theme-text);
  padding: calc(var(--theme-spacing-unit) * 4);
}

.button {
  background: var(--theme-primary);
  color: white;
  border-radius: var(--theme-border-radius);
}
```

### Rules
- ✅ Use theme variables for colors users should control
- ✅ Provide fallbacks: `var(--theme-primary, #0066cc)`
- ✅ Test with multiple theme combinations
- ❌ Don't hardcode colors that should be themeable
- ❌ Don't use theme variables in editor UI

## Layer 2: Editor UI Styles (Fixed)

### Purpose
Puck editor chrome - sidebars, toolbars, canvas frame.

### Technology
Global CSS file with class-based overrides.

### Scope
- Editor components (NOT page content)
- Left sidebar (component list)
- Right sidebar (properties panel)
- Header (save/publish buttons)
- Canvas frame

### User Control
**None.** Editor UI is not customizable by end users.

### Implementation
```css
/* src/styles/puck-theme.css */

/* Transparent sidebar backgrounds */
.puck-themed-wrapper {
  /* Override Puck's default styles */
}

/* Fixed light mode for canvas */
.puck-canvas-light-mode {
  --puck-color-grey-01: #181818;
  color-scheme: light !important;
  /* Prevents theme from affecting editor chrome */
}
```

### Rules
- ✅ Only style Puck's own UI components
- ✅ Use CSS classes to target specific elements
- ✅ Keep independent of user themes
- ❌ Don't use for page content
- ❌ Don't use theme variables

## Layer 3: Block Component Styles

### Purpose
Block-specific styling and layout.

### Technology
CSS Modules + Tailwind + Inline (for dynamic values only).

### When to Use What

#### CSS Modules: Component-Specific Styles
```typescript
// TableBlock/styles.module.css
.container {
  border: 1px solid var(--theme-border);
  border-radius: var(--theme-border-radius);
}

.header {
  font-weight: 600;
  border-bottom: 1px solid var(--theme-border);
}

// TableBlock/TableBlock.tsx
import styles from './styles.module.css';

export function TableBlock(props) {
  return <div className={styles.container}>...</div>;
}
```

#### Tailwind: Layout Utilities
```typescript
export function MetricBlock(props) {
  return (
    <div className="flex items-center gap-4 p-6">
      <div className="flex-1">...</div>
      <div className="w-24">...</div>
    </div>
  );
}
```

#### Inline Styles: Dynamic Values ONLY
```typescript
// ✅ Good: Dynamic viewport width
<div style={{ width: viewport === "desktop" ? "100%" : `${viewportWidths[viewport]}px` }}>

// ✅ Good: Dynamic theme injection
<div style={{ ...theme.toCSSVariables() }}>

// ❌ Bad: Static value that should be CSS
<div style={{ marginTop: '1rem' }}> // Should be CSS or Tailwind
```

### Decision Matrix

| Use Case | Technology | Example |
|----------|------------|---------|
| User-customizable colors | Theme variables | `color: var(--theme-primary)` |
| Block-specific layout | CSS Modules | `.grid { display: grid; }` |
| Quick spacing/flex | Tailwind | `className="flex gap-4"` |
| Runtime-calculated | Inline | `width: ${width}px` |
| Editor UI only | puck-theme.css | `.puck-sidebar { }` |

## Examples

### ✅ Good: Theme-Aware Block

```typescript
// TableBlock/TableBlock.tsx
import styles from './styles.module.css';

export function TableBlock(props: TableBlockProps) {
  return (
    <div className={`${styles.container} flex flex-col gap-2`}>
      {/* CSS Module + Tailwind */}
      <div className={styles.header}>
        {/* Uses --theme-text from styles.module.css */}
        <h3>{props.title}</h3>
      </div>
      <div className="overflow-x-auto">
        {/* Tailwind utility */}
        <table className={styles.table}>
          {/* Uses --theme-border from styles.module.css */}
          {props._rows?.map(row => ...)}
        </table>
      </div>
    </div>
  );
}

// TableBlock/styles.module.css
.container {
  background: var(--theme-surface, white);
  border: 1px solid var(--theme-border, #e5e7eb);
  border-radius: var(--theme-border-radius, 0.5rem);
}

.header {
  color: var(--theme-text, #1f2937);
  padding: calc(var(--theme-spacing-unit, 0.25rem) * 4);
  border-bottom: 1px solid var(--theme-border, #e5e7eb);
}

.table {
  width: 100%;
  color: var(--theme-text, #1f2937);
}
```

### ✅ Good: Editor UI Override

```css
/* puck-theme.css */

/* Make sidebars transparent */
.puck-themed-wrapper [data-puck-portal-root] {
  background: transparent !important;
}

/* Fix canvas to light mode (not user-themeable) */
.puck-canvas-light-mode {
  --puck-color-grey-01: #181818;
  --puck-color-grey-02: #2a2a2a;
  color-scheme: light !important;
}
```

### ❌ Bad: Mixed Concerns

```typescript
// ❌ Don't do this
export function Block(props) {
  return (
    <div style={{
      // Static values in inline styles
      marginTop: '1rem', // Should be Tailwind or CSS Module
      padding: '16px',   // Should be Tailwind or CSS Module

      // Theme variable in inline style (works but prefer CSS)
      background: 'var(--theme-primary)', // Should be CSS Module

      // Hardcoded color (not themeable)
      color: '#333', // Should use --theme-text
    }}>
      ...
    </div>
  );
}
```

## Migration Checklist

When creating/updating a block:

### 1. Identify User-Customizable Elements
- [ ] Which colors should users control?
- [ ] Which spacing should respond to theme?
- [ ] Which borders should use theme radius?

### 2. Create CSS Module
```css
/* Block/styles.module.css */
.element {
  /* Use theme variables */
  color: var(--theme-text);
  background: var(--theme-surface);

  /* Block-specific that won't change */
  display: grid;
  grid-template-columns: 1fr 2fr;
}
```

### 3. Use Tailwind for Layout
```typescript
<div className="flex items-center justify-between gap-4">
```

### 4. Only Inline for Dynamic
```typescript
style={{ width: `${dynamicWidth}px` }}
```

### 5. Test Themes
- [ ] Try light theme
- [ ] Try dark theme (if supported)
- [ ] Try high-contrast
- [ ] Try custom colors

---

## Consequences

### Positive
- **Clear separation:** Each layer has defined purpose
- **User control:** Theme system enables customization
- **Consistency:** Blocks inherit theme automatically
- **Performance:** CSS variables are fast
- **Maintainability:** Know where each style lives

### Negative
- **Learning curve:** Developers must understand 3 layers
- **Verbosity:** CSS variables require fallbacks
- **Migration:** Existing blocks need updates
